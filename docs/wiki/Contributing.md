# Contributing and documentation corrections

Search [issues](https://github.com/nyameko/quantum-platform/issues) and [PRs](https://github.com/nyameko/quantum-platform/pulls); open an issue in the repository owning the failing behavior. A useful issue includes the user journey, environment/version, minimal sanitized reproduction and expected/observed outcome.

For code contributions, use a review branch, include UI + API test coverage for any behavior change, ensure permissions are server-side, run Node/Python checks and explain migration/release implications. For docs, label capabilities as implemented, live-accepted, experimental or planned; link the source route, test and release evidence; keep command snippets executable and least-privilege. Do not overwrite historical migration tutorials to make them appear current.

Read [Developer guide](Developer-guide.md) and [wiki publication policy](https://github.com/nyameko/quantum-platform/blob/main/docs/WIKI_PUBLISHING.md).
